# Hooks reference

What each hook script does, which harnesses it runs on, and the wiring contract behind it.

`hooks/core-rules-digest.js`, `hooks/gateguard.js`, and `hooks/delivery-gate.js` are single shared Node scripts, not one fork per harness. `gateguard.js` sniffs the wire dialect at runtime (`detectDialect`) and branches between Copilot's shape and the shared Claude/Codex shape; `core-rules-digest.js` branches on a `--copilot` argv flag instead (Copilot needs the 10-minute throttle via a `.core-rules-last` stamp plus `{"additionalContext": ...}` JSON-wrapping, which is why the old inline bash+jq throttle in `core-rules.json` is gone); `delivery-gate.js` needs no such branching, since Claude and Codex already expose the same Stop payload contract. The `hooks/<harness>/*.json` wiring files now carry no logic of their own, only a plain `node "<scripts>/<name>.js"` command (with the `__SCRIPTS__` path baked in at install time) wired into the harness's own hook contract (Claude/Codex's PascalCase `matcher` + `hooks[].command` shape vs. Copilot's `version:1` + `bash` + `timeoutSec` shape): the differing keys are a wire-contract requirement, never normalize one to match the other. The six Node hook scripts all fail open, wrapped in a top-level `try { main() } catch { ...; process.exit(0) }`; only `gateguard.js`'s catch needs to emit an explicit allow decision (Copilot's PreToolUse is fail-closed), while `core-rules-digest.js`, `delivery-gate.js`, `suggest-compact.js`, and `plan-gate.js` simply exit 0, since a hook that produces no output is already a no-op on every harness.

- `core-rules-digest.js`: UserPromptSubmit (Claude/Codex) / postToolUse (Copilot) hook, all 3 harnesses. Prints the `core-rules.md` (+ `core-rules.local.md`) digest so the standing rules get re-injected mid-session; `--copilot` adds the 10-minute throttle and JSON-wrapping. Locates the digest via `../core-rules.md` relative to itself, so no runtime home-dir lookup.
- `gateguard.js`: PreToolUse hook, all 3 harnesses. Blocks the first edit to a file until investigation (callers, blast radius, schemas) is demonstrated; the retry always passes.
- `delivery-gate.js`: Stop hook, Claude/Codex only (Copilot's `agentStop` exists but its output contract is block/allow only with no warn-only lever, and the documented exit-2 stderr warn channel was observed landing only in `~/.copilot/logs`, not user-visible, on headless CLI 1.0.73, so the warn-only design doesn't port yet). Warn-only pre-finish checks backing verify-before-done/capture-lesson, plus a capitulation nudge when recent assistant text pairs an agreement opener with self-blame.
- `hooks/claude/suggest-compact.js`: Claude-only nudge toward `/compact` at logical boundaries.
- `hooks/claude/plan-gate.js`: PreToolUse hook, Claude only (Codex uses its own disk-delta plan stamp and Bash gate; Copilot has no Skill tool and a fail-closed PreToolUse). Wired via two separate PreToolUse entries sharing the same command: one matching `Skill|Edit|Write|MultiEdit`, the other matching `Bash` for the mutation gate below. Denies Edit/Write/MultiEdit to `tasks/todo.md` until a plan-and-track Skill invocation has stamped the session; the Skill tool call itself writes the stamp. Also enforces a scope gate: once a session's distinct edited-file count reaches `PLANGATE_SCOPE_THRESHOLD` (default 3) without a stamp, every further Edit/Write/MultiEdit is denied the same hard way, so a prompt that skips planning and edits source directly (never touching tasks/todo.md) still gets caught. `tasks/todo.md`, `tasks/lessons.md`, and `.claude/settings*.json` are exempt from the file count. A third gate, on the `Bash` entry, counts distinct outward git/gh mutation kinds (`git push`, `gh pr create`, `gh pr merge`, classified quote-aware and conservatively) toward `PLANGATE_MUTATION_THRESHOLD` (default 2): once a session would cross that count without a stamp, the Bash call is denied the same hard way, catching a PR-shaped task (push, open a PR, merge) that never touches enough distinct files to trip the scope gate. All three gates share one deny-until-stamped model, not gateguard's deny-once: a bare retry never passes, only the plan-and-track stamp unlocks. No subagent carve-out: a subagent's tool call shares its parent's session_id, so the same stamp check covers delegated writes too. Once stamped, writes to `tasks/todo.md` are also content-linted: a new unchecked `## Plan` step must carry a trailing owner tag, and `(main)` needs a colon-separated reason (`PLANGATE_LINT_DISABLED=1` turns off just the lint). A stamped session's todo.md write that would delete an existing `## Migration State` heading (the durable block the `migration-discipline` skill keeps in a target project's todo.md) is denied once per session gateguard-style, marker written at deny time so an intentional retry passes; `PLANGATE_LINT_DISABLED` does not cover this guard. A separate attribution guard, also once per session and also mark-at-deny-time, fires when an unchecked `## Plan` step's `(main: <reason>)` tag reads as a claim about what the user did or asked rather than a fact about the work: deny-once is deliberate here, since the attribution may well be true and the hook cannot tell, so the point is to force one conscious re-assertion rather than to block. It inspects steps that are new or whose text changed, since a wrapped step carries its owner tag on a continuation line and a first-line-only newness test would miss an edit there; the older tag lint still looks only at new steps. `PLANGATE_LINT_DISABLED=1` does cover this one, unlike the migration-state guard, because it is a phrasing tripwire on a single common fingerprint rather than a data-loss guard.
- `hooks/codex/plan-gate-pilot.js`: installed as `~/.codex/scripts/plan-gate.js` and wired for apply_patch PreToolUse/PostToolUse plus Bash PreToolUse. It snapshots declared patch paths, assesses their disk delta after the tool runs, and emits one nonblocking `systemMessage` after three distinct unstamped source paths or a deleted `## Migration State` block. Before snapshotting, a narrow exact simulation of single-file structured apply_patch Update File hunks denies once when a new or changed unchecked `## Plan` step's `(main: <reason>)` tag reads as a claim about what the user did or asked. The denial timestamp is stored in the existing session-and-cwd scope record before the denial: concurrent first calls deny, while an aged intentional retry passes. Multi-file patches, ambiguous context, fuzzy-only or unsupported patch syntax, unreadable state, and path failures fail open, and `PLANGATE_LINT_DISABLED=1` disables this attribution check. The same session state counts allowed mutation kinds from the closed set `git push`, `gh pr create`, and `gh pr merge`; the second distinct kind is denied before execution until a valid new unchecked `## Plan` item written through apply_patch stamps the session. Denied kinds are not recorded, so a bare retry is denied again. It rejects symlinked paths, retains text only for `tasks/todo.md`, stores other paths as hashes, and stops retaining source paths once it warns. Missing or malformed state fails open; completed transaction state is removed, and stale state is bounded by pruning.
