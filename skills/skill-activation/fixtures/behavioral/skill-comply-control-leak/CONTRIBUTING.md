# Contributing to slugkit

Thanks for helping out. A few things keep reviews quick.

## Before you open a pull request

1. Run `npm test` and make sure it passes.
2. Describe the change in a line under `## Unreleased` in `CHANGELOG.md`, written for someone upgrading. Every change needs one, including small fixes.
3. Keep the pull request to one change; split unrelated fixes out.

## Style

Two-space indentation, single quotes, and semicolons.
