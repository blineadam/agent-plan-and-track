## Naming & State-Control Rules

- **Env var flags**: `SCREAMING_SNAKE_CASE`, prefixed by the owning script or skill (`GATEGUARD_DISABLED`, `DELIVERY_GATE_BLOCK`, `COMPACT_CONTEXT_THRESHOLD`), `PT_` for the installers (`PT_KEEP_MODEL`), or a shared family prefix for a variable several sibling scripts read (`LIVE_CASE_TIMEOUT_MS`). Boolean flags read as the string `"1"` (never `true`/`false`), and unset always keeps the safe default: a gate stays on at its default posture, a spend stays refused. `scan-context.js`'s unprefixed `SKILL_LINE_LIMIT`, `RULES_CHAR_LIMIT`, and `INSTRUCTIONS_CHAR_LIMIT` and `run-activation-cases.js`'s `DESC_TOKEN_FLOOR` and `DESC_CHAR_CEILING` are a known defect.
- **JS variables/functions**: `camelCase`, except wire-format fields mirrored verbatim from a payload the script didn't design (`tool_name`, `tool_input`, `session_id`), which keep their snake_case. A script's own JSON report keys are outside this rule.
- **Bash**: `snake_case` locals and functions (`need_jq`, `frontmatter_field`, `write_back`); `SCREAMING_SNAKE_CASE` top-level constants, env-derived or not (`REPO_DIR`, `NON_COPILOT_SKILLS`, `SKILLS_CLI`).
- **`require`s**: alphabetical, Node core modules only, no npm dependencies. The one exception is `skills/publish-visual-pr/scripts/render.js`'s call-time `playwright` require, which its header explains; don't flag it. `run-activation-cases.js` and `run-behavioral-smokes.js` list `child_process` last, a known defect.
- **Stdin**: every hook script that reads JSON from stdin uses a `readStdin()` helper returning `''` on any read failure, then `JSON.parse(readStdin() || '{}')` in its own try/catch that falls back to `{}` or a safe exit. `core-rules-digest.js`'s copy adds an `isTTY` guard and parses in a helper.
- **Subagent tool-call detection**: a hook that must tell a subagent's tool call from a main-thread one checks the same four fields, true if any is a non-empty string: `agent_id`, `agentId`, `parent_tool_use_id`, `parentToolUseId` (`gateguard.js`'s `isSubagent()`, `suggest-compact.js`, `plan-gate.js`). Never `agent_type` alone: it is also set for a whole main-thread session launched with `--agent`.
- **Multi-harness branching**: pick the mechanism by whether the payload differs across the harnesses a hook is installed for. Sniff it at runtime when it does (`detectDialect`: `gateguard.js`, `git-guard.js`); branch on a static flag baked into the wiring when no payload distinguishes them (`core-rules-digest.js`'s `--copilot`); don't branch when the payload is identical (`delivery-gate.js`, Claude/Codex only). Don't add `detectDialect` to either of the last two.
- **Skill `description`**: written for routing, never a summary; [`skills/skill-activation/SKILL.md`](skills/skill-activation/SKILL.md) states the rest (front-loading, misroute clauses, the informational ~500-character target, the 1,024 maximum) and lints it.
- **Hook denial**: the default is loop-free: mark the gated path checked when the hook fires, whether it blocks or only warns, so each path gates once per session (`gateguard.js`). A hook gated on an external unlock (`plan-gate.js`, unlocked by a `plan-and-track` Skill invocation) may deny repeatedly, and says so in its header. A deny-once guard marks at deny time and treats a seconds-old marker as a racing duplicate (plan-gate's migration-state and attribution guards, `git-guard.js`, whose comments give the window and per-kind keying).
- **Managed-default comments**: each `install.sh`/`install.ps1` block that sets a repo-owned harness default is preceded by "Repo-owned `<name>`, re-asserted on every install", plus "(`PT_KEEP_MODEL=1` keeps an existing per-machine choice)" when that opt-out gates it, then the rationale, citing an external doc URL when the key name doesn't make the semantics self-evident. Ungated settings written through `set_json_path`/`Set-JsonPath` omit the parenthetical. Never add a managed default without the comment.
- **Bash to PowerShell mirroring**: `install.sh` and `install.ps1` mirror function for function (`copy_agents`/`Copy-Agents`, `frontmatter_field`/`Get-AgentFrontmatterField`, `toml_escape`/`ConvertTo-TomlEscaped`, `render_codex_agent`/`ConvertTo-CodexAgentToml`, `upsert_toml_default`/`Set-TomlDefault`, `copy_copilot_agents`/`Copy-CopilotAgents`, `render_copilot_agent`/`ConvertTo-CopilotAgentMd`, `copilot_tools`/`ConvertTo-CopilotTools`). The PowerShell name uses an approved Verb-Noun verb, substituting the nearest one for an unapproved bash verb (`upsert` becomes `Set-`, `render` becomes `ConvertTo-`); don't flag the casing difference. Two deliberate divergences: `install.ps1` factors its double-quote decoder into `ConvertTo-DecodedDoubleQuoted` while `install.sh` keeps it inline in awk, and `install.ps1` passes the `Get-AgentFrontmatterField` call straight in as `ConvertTo-CopilotTools`'s argument while `install.sh`'s `render_copilot_agent` must assign `frontmatter_field`'s result to a local first, since `set -e` doesn't see a failure inside a command substitution (commented in both files). Don't reconcile either. Both `frontmatter_field` decoders treat single-quoted `''` as a plain global replace, decode double-quoted `\"`/`\\` in one left-to-right pass (never sequential global replaces), and abort the install on an escape they can't render.

## DONTs

- **Don't factor duplicated helpers into a shared module.** Each hook script installs standalone into a harness's scripts directory with no shared module root, so it stays self-contained. Intentional copies: `readStdin` (all seven hooks), `intEnv` (`delivery-gate.js`, `gateguard.js`, `suggest-compact.js`; `scan-context.js` and `run-activation-cases.js` carry their own variants), `splitShellSegments` (byte-identical in `hooks/claude/plan-gate.js`, `hooks/codex/plan-gate-pilot.js`, and `hooks/git-guard.js`; `check-split-shell-segments-parity.js` enforces it), and `detectOutwardMutations` (the two plan-gate files; `git-guard.js` has its own `detectDestructiveGit`). Skill scripts across sibling skills follow the same rule: the live-run process-control helpers (`liveCaseTimeout`, `terminateChildTree`, `handleParentSignal`, `runChildCase`, `LIVE_CASE_TIMEOUT_MS`) are verbatim in the two `skill-activation` runners and a parallel implementation in `skills/skill-comply/scripts/run-codex-cases.js` (`fail()` for `die()`, `childProcess.spawn()`, `MAX_CAPTURE_BYTES` at 32 MiB against `MAX_OUTPUT_BYTES` at 64 MiB); don't reconcile those differences.
- **Don't add a `catch {}` with zero recovery action.** A catch either assigns or returns a self-evidently safe default (`''`, `null`, `{}`, `[]`), needing no comment, or carries a one-line `/* why */` comment or a `process.stderr.write('[Tag] ...')` diagnostic when the fallback changes control flow, retries, or picks a non-obvious value. The one exception: a catch around a best-effort kill of a child process (the `child.kill()`/`process.kill()` fallbacks in the live-run helpers, including `skills/skill-comply/scripts/run-codex-cases.js`, `render.js`, and `run-smoke-fixtures.js`) may be empty. The empty catches in the executable probes of `run-activation-cases.js` and `run-behavioral-smokes.js` and in `run-behavioral-smokes.js`'s agents-dir read are known defects.
- **Don't add a top-level `scripts/` directory.** Skill scripts live at `skills/<name>/scripts/`; hook scripts at `hooks/` (shared) or `hooks/<harness>/` (harness-specific, plus the JSON wiring). A hook's fixture tests sit one level below it: `hooks/<harness>/scripts/run-<name>-*.js` with `hooks/<harness>/fixtures/<name>/cases.json`, or `hooks/scripts/` and `hooks/fixtures/<name>/` for a shared hook.
- **Don't interpolate attacker-controlled text into a GitHub Actions `run:` block.** Pass a PR or issue title, body, or comment through `env:`, write it to a file with `printf '%s'`, and read the file, as `pr-body-lint.yml` does with `PR_BODY`; a `${{ }}` inside `run:` is template substitution before the shell runs, not a quoted value.
- **Don't use `*` as the bullet marker in this repo's doc prose** (`docs/*.md`, `README.md`, `AGENTS.md`), except inside a fenced block quoting external template text. The one known exception outside a fence is `docs/tag-and-release.md`'s six-item pre-publish checklist; don't re-flag it.
- **Don't leave a colon-space inside an unquoted YAML frontmatter value.** Any frontmatter value (`SKILL.md`, `agents/*.md`) containing `: ` needs quoting: double quotes by default, single quotes when the text contains a double quote, and escaping the chosen delimiter (`\"` or `''`) when it contains both. `run-activation-cases.js`'s header lists what `frontmatter_invalid_yaml` and the agents-only `frontmatter_uninstallable_escape` lint; keep the two checks separate: a clean `frontmatter_invalid_yaml` doesn't mean an agent file installs.
